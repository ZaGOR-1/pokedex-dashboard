# Pokédex Analytics

Навчальний проєкт із дисципліни **«Компонентно-орієнтоване програмування»**.

**Лабораторна робота №2. Заочна форма. Варіант №6: Pokédex.**

Мета роботи: навчитися завантажувати дані з API, показувати їх у таблиці, сортувати записи та обробляти помилки.

## Що працює

- Завантаження 20 Pokémon із PokeAPI.
- Таблиця з ID, назвою, типами, HP, атакою та захистом.
- Сортування за ID, назвою та HP за зростанням і спаданням. Для цього потрібно натиснути заголовок стовпця.
- Чотири KPI: загальна кількість записів API, кількість Pokémon у вибірці, унікальних типів і Pokémon із двома типами.
- Фільтр за типом і його скидання.
- Повідомлення про завантаження, помилку та відсутність даних. Після помилки можна повторити запит кнопкою.
- Лічильник місць у команді від 0 до 6, світла й темна тема.
- Адаптивна сторінка. На вузькому екрані таблиця прокручується у своїй області.

## Технології

React 19, TypeScript, Vite та CSS. Для тестування використано Vitest і React Testing Library, для перевірки коду та форматування: ESLint і Prettier.

## Встановлення та запуск

Потрібні Node.js `^22.22.2`, `^24.15.0` або `>=26.0.0` та npm.

```bash
git clone https://github.com/ZaGOR-1/pokedex-dashboard.git
cd pokedex-dashboard
npm ci
npm run dev
```

Відкрийте адресу, яку покаже Vite в терміналі, зазвичай `http://localhost:5173`. Для завантаження даних потрібен доступ до PokeAPI.

Збірка та перегляд готової версії:

```bash
npm run build
npm run preview
```

## Перевірки

```bash
npm run lint
npm run typecheck
npm run format:check
npm run test
npm run build
```

Тести перевіряють завантаження даних, обробку помилок, сортування, фільтр, KPI, лічильник і тему. У тестах використовуються підготовлені відповіді API, тому доступ до мережі для них не потрібний.

## Організація коду

- `src/app/`: головний компонент, який збирає сторінку.
- `src/components/`: таблиця, KPI, лічильник, тема та завантаження даних через `useEffect` і `useState`.
- `src/domain/pokemon/`: модель Pokémon, фільтрація, сортування та підрахунок показників.
- `src/application/pokemon/`: опис результату завантаження.
- `src/infrastructure/pokeapi/`: запити до PokeAPI, перевірка й перетворення відповідей.
- `tests/`: налаштування та дані для тестів. Тести компонентів лежать поруч із відповідними файлами в `src/`.

## Обмеження

- Завантажується лише перша сторінка з 20 записів. Фільтр і сортування працюють у межах цієї вибірки. Пошуку всієї бази та перемикання сторінок поки немає.
- Загальний KPI враховує записи API, включно з формами Pokémon. Решта KPI описують усю завантажену вибірку й не змінюються від фільтра.
- У фільтрі залишено 18 стандартних типів. Інші типи з коректними назвами показуються в таблиці без окремого варіанта у фільтрі.
- Якщо не вдається завантажити хоча б один запис, сторінка показує помилку. Стан віджетів не зберігається після перезавантаження.

Джерело даних: [PokeAPI](https://pokeapi.co/). Pokémon належать їхнім правовласникам. Проєкт призначений для навчання.
