# Pokédex Analytics

Навчальний проєкт із дисципліни «Компонентно-орієнтоване програмування».

**Лабораторна робота №5. Заочна форма. Варіант №6: Pokédex.**

Мета роботи: перенести спільний стан у Zustand, додати обраних Pokémon та два типи графіків. Застосунок продовжує лабораторні роботи №1–4.

## Що працює

- Дашборд `/` із таблицею, фільтрами, чотирма KPI та графіком.
- Сторінка `/pokemon/:id`: шість базових характеристик, зображення, типи, здібності та дерево еволюцій із розгалуженнями.
- Перехід до деталей за назвою в таблиці, посилання «Назад», прямі адреси та оновлення сторінки.
- Світла й темна тема на всіх маршрутах.
- Обране: додавання й видалення в таблиці та деталях. Кнопки показують спільний стан і працюють клавішами Enter та Space.
- Контрольована форма React Hook Form: назва, тип і мінімальний HP. Назва застосовується через 400 мс після введення, решта полів одразу.
- HP приймає невід’ємні цілі числа в межах точних цілих JavaScript. Некоректний ввід не змінює активний поріг і показує повідомлення. Порожнє поле прибирає обмеження, нуль є допустимим значенням.
- Скидання фільтрів без зміни теми, обраного, режиму графіка, лічильника та поточного сортування.
- Сортування ID, назви та HP в обох напрямках.
- Loading, помилка з ручним повтором, порожня відповідь API та відсутність збігів після фільтрації.
- Лічильник місць у команді від 0 до 6. Він незалежний від обраного.
- Адаптивне оформлення та прокручування таблиці всередині її області.

## Технології

React 19, TypeScript, Vite, React Router 7, React Hook Form, Zustand 5, Recharts 3 та CSS. Перевірки: Vitest, React Testing Library, Playwright, ESLint і Prettier.

Для графіків установлено `react-is` тієї самої версії, що й React. Зафіксовані версії залежностей містяться в `package-lock.json`.

## Встановлення та запуск

Потрібні Node.js `^22.22.2`, `^24.15.0` або `>=26.0.0` та npm.

```bash
git clone https://github.com/ZaGOR-1/pokedex-dashboard.git
cd pokedex-dashboard
npm ci
npm run dev
```

Відкрийте адресу, яку покаже Vite, зазвичай `http://localhost:5173`. Для отримання реальних даних потрібне з’єднання з PokeAPI.

```bash
npm run build
npm run preview
```

Для статичного хостингу потрібно налаштувати повернення `index.html` для маршрутів застосунку. Локально прямі адреси перевірені через Vite preview.

## Спільний стан

`src/app/dashboardStore.ts` містить один Zustand store:

| Поле          | Призначення                                |
| ------------- | ------------------------------------------ |
| `theme`       | Світла або темна тема                      |
| `filters`     | Введена назва, тип і рядок мінімального HP |
| `favoriteIds` | Унікальні ID обраних Pokémon               |
| `chartType`   | `bar` або `line`                           |

Компоненти читають стан через selectors, змінюють через actions. Повторне додавання ID або встановлення того самого значення не створює зайвого оновлення. Окремі selectors розташовані в `dashboardSelectors.ts` і повертають наявні посилання або прості значення.

`ThemeRoot` читає тему зі store та застосовує `data-theme` до спільної оболонки. Власні ThemeContext і PokemonFiltersProvider прибрані під час переходу від ЛР №4 до ЛР №5.

React Hook Form працює всередині `PokemonFilterForm`. `Controller` зберігає контракт `value`/`onChange`, обробляє поля та валідацію. Параметр `useForm({ values })` отримує активні значення зі store. Обробники змін викликають actions; власних ефектів для двосторонньої синхронізації немає. Інші частини застосунку не читають фільтри зі стану бібліотеки форм.

`FavoriteButton` читає обраність за ID зі store. Тому зміна в таблиці видима в деталях і навпаки. Обране не залежить від фільтрів, сортування або наявності Pokémon серед перших 20 записів. Повні відповіді PokeAPI в обраному не зберігаються.

HTTP-відповіді, стани запитів, кеш, поточний ID маршруту, сортування та Counter до store не перенесені.

## Графіки та охоплення даних

Графік показує середні базові характеристики відфільтрованих Pokémon: HP, атаку, захист, спеціальну атаку, спеціальний захист і швидкість. Перемикач змінює стовпчиковий графік на лінійний і назад. Лінія показує профіль характеристик, а не зміну в часі.

`PokemonDashboard` один раз фільтрує завантажений список. Той самий масив надходить до таблиці, KPI вибірки й графічного віджета. Зміна назви після debounce, типу, HP або reset оновлює їх разом. Сортування змінює лише порядок рядків.

Чиста функція `getAverageStats` рахує середнє кожної характеристики окремо. `null` і відсутні значення пропускаються, справжній нуль враховується. Для кожного показника є власна кількість відомих значень. Якщо значень немає, показується «Невідомо». Числа округлюються до одного десяткового знака лише для відображення.

Обидва графіки отримують однакові дані. Є tooltip із числами, підтримка клавіатури та текстовий список шести значень. Для порожньої вибірки показується повідомлення замість SVG. Дані графіка не зберігаються у store.

Статистика стосується лише першої завантаженої сторінки, до 20 Pokémon. Це не середні значення всієї бази PokeAPI.

## Завантаження й навігація

Власний `useFetch<T, P>(request, params)` повертає `data`, `loading`, `error` та `refetch`. Під час зміни запиту, параметрів або повтору попередній запит скасовується. Пізні відповіді скасованих запитів ігноруються. `useDebounce` затримує назву на 400 мс і прибирає таймер при зміні значення або демонтуванні.

`PokeApiClient` завантажує `/pokemon?limit=20&offset=0`, потім характеристики записів групами до чотирьох запитів. Усі шість характеристик беруться з цих відповідей. Окремих HTTP-запитів для графіка немає. Успішна сторінка кешується в пам’яті клієнта, помилки не кешуються.

Деталі завантажуються за ID із URL. Далі отримуються species та evolution chain за посиланнями PokeAPI. Некоректний ID не створює запиту. 404 відрізняється від помилки мережі. Помилка еволюцій не ховає інші деталі; відсутнє або зламане зображення замінюється текстом.

| Дія                                              | Результат                                                           |
| ------------------------------------------------ | ------------------------------------------------------------------- |
| Список → деталі → назад                          | Тема, фільтри, обране й тип графіка зберігаються                    |
| Повернення до списку                             | Успішний кеш використовується без повторного HTTP                   |
| Фільтрація, сортування, обране або зміна графіка | Додаткових HTTP-запитів немає                                       |
| Прямі деталі                                     | Список не завантажується; кнопка обраного працює                    |
| Повний reload або нова вкладка                   | Початкові фільтри, світла тема, порожнє обране, `bar`; кеш порожній |

localStorage і persist не використовуються. Сортування та Counter локальні для головної сторінки й починаються спочатку після повернення з деталей.

## Як перевірити

```bash
npm run lint
npm run typecheck
npm run format:check
npm run test
npm run build
```

Unit та integration тести перевіряють store, selectors/actions, форму, обране, обчислення, справжні компоненти Recharts і попередні функції. Store скидається перед кожним тестом. HTTP-відповіді підготовлені, доступ до мережі не потрібний.

Для браузерних тестів один раз установіть Chromium:

```bash
npx playwright install chromium
npm run test:browser
```

Playwright запускає production preview на порту 4174 із підготовленими відповідями API. Перевіряються SVG обох графіків, tooltip, зміна чисел після кожного фільтра, обране між маршрутами, клавіатура, reload, 404, retry, курсор у полі й швидкий reset. Перевіряються обидві теми та ширини 320/375/768/1280 px.

Для ручної перевірки:

1. Введіть `saur`, виберіть `poison` та HP `60`. У реальній першій сторінці очікуються Ivysaur і Venusaur. Середні характеристики: 70, 72, 73, 90, 90, 70. Склад відповіді залежить від PokeAPI.
2. Перемкніть тип графіка. Числа мають залишитися тими самими.
3. Додайте Ivysaur до обраного, відкрийте деталі, видаліть його та поверніться. Кнопка в таблиці має відобразити зміну; фільтри, тема й режим графіка зберігаються.
4. Укажіть HP `999`, перевірте порожній результат, потім скиньте фільтри.
5. Відкрийте `/pokemon/133` для восьми гілок Eevee; `/pokemon/abc`, `/pokemon/999999` і `/missing` для повідомлень про неправильні адреси.
6. Оновіть сторінку та перевірте скидання стану вкладки.

## Організація коду

- `src/app/`: маршрути, store, selectors, оболонка теми, керування фокусом і зв’язування залежностей.
- `src/components/`: форма, таблиця, KPI, обране, графік, перемикач і Counter.
- `src/hooks/`: власні `useDebounce` та `useFetch`.
- `src/domain/pokemon/`: моделі, фільтрація, сортування, KPI та середні характеристики. Без React і HTTP.
- `src/application/pokemon/`: контракти завантаження й отримання деталей та еволюцій.
- `src/infrastructure/pokeapi/`: HTTP, перевірка відповідей і перетворення в доменні моделі.
- `tests/`: налаштування, fixtures і браузерні сценарії. Решта тестів лежить поруч із відповідним кодом.

## Обмеження

- Немає глобального пошуку, пошуку за ID у формі та пагінації. Пошук назви, тип і HP працюють лише серед завантажених записів; це вказано біля форми й графіка.
- Загальний KPI показує `count` Pokémon endpoint, включно з формами. Решта KPI описують відфільтровану вибірку: кількість Pokémon, унікальних типів і записів із двома типами. Це не глобальний розподіл кількості Pokémon за кожним типом.
- У фільтрі залишено 18 стандартних типів. Інші коректні типи відображаються в таблиці.
- Якщо один запис сторінки не завантажився, дашборд показує помилку. Еволюції відображаються без умов переходів.
- Recharts збільшує розмір JavaScript. Поточна збірка має попередження Vite про пакет понад 500 kB; окреме завантаження графіків поки не налаштоване.
- Автоматичні браузерні перевірки виконуються в Chromium. Firefox, Safari та роботу зі скринрідером окремо не перевірено.

Джерело даних: [PokeAPI](https://pokeapi.co/docs/v2). Pokémon належать їхнім правовласникам. Проєкт призначений для навчання.
